## 1. היקף

**בפנים:**
- דשבורד ("בית") מלא, בטלפון ובמחשב.
- מסך "נושאים".
- מסך "בעיה רפואית / בירור" (`#/issue/:id`).
- "בירור חדש" גם במצב עריכה (`#/issue/:id/edit`), כולל סגירת בירור.

## 2. נתיבים (router)

| נתיב | מסך | מסגרת |
|---|---|---|
| `#/` | דשבורד | Shell (nav: home) |
| `#/issues` | נושאים | Shell (nav: issues) |
| `#/issue/:id` | בעיה רפואית | **Shell** עם סרגל ניווט תחתון, "נושאים" פעיל, אבל עם כותרת וחץ חזרה במקום לוגו (DESIGN: "בשאר המסכים (כולל בעיה רפואית) יש כותרת וחץ חזרה" + סרגל ניווט תחתון) |
| `#/issue/new` | בירור חדש (יצירה) | Flow (קיים) |
| `#/issue/:id/edit` | בירור חדש (עריכה) | Flow |
| `#/document/:id` | המסמך המקורי (שמור) | Flow |

**שינויים ב-`js/router.js`:**
- התאמת נתיבים עם פרמטר: פונקציה קטנה `matchRoute(path)` שבודקת קודם נתיבים קבועים ואז תבניות (`/issue/:id`, `/issue/:id/edit`, `/document/:id`) ומחזירה `{ render, params }`. `'/issue/new'` נבדק לפני `/issue/:id`.
- `shell(active, opts)`: אפשרות `opts.header = { title, onBack, action }` למסך הבעיה — אזור כותרת בצבע Coral Zone עם חץ חזרה, נקודת צבע, שם הבירור וכפתור "עריכה". שאר ה-shell (סרגל תחתון, FAB, הבהרה) נשאר. במחשב: אותו מסך בתוך ה-shell הרגיל עם הכרטיסיות העליונות ("נושאים" פעיל), והכותרת עם החץ מתחת להן.
- **חזרה:** היום `backPath()` זוכר רק את מסך ה-shell האחרון. מסך הבעיה הופך גם הוא ל-"shell" לצורך זה, כך שחזרה מ"עריכה" או מ"המסמך המקורי" חוזרת למסך הבעיה. החץ במסך הבעיה עצמו חוזר ל-`#/issues` אם הגיעו משם, ואחרת לבית. מימוש: `lastShellPath` ו-`prevShellPath` (שתי רמות מספיקות לזרימות של המסמכים: בית/נושאים ← בעיה ← עריכה/מסמך).
- `#/add/original` נשאר כמו שהוא (מסמך לפני שמירה).

## 4. גישה לנתונים (`js/data.js`)

כל קריאה מחזירה רק את השדות שצריך. RLS מגן; אין סינון לפי `user_id` בקוד.

| פונקציה | שאילתה |
|---|---|
| `listOpenTasks()` | `tasks` עם `status in (todo, waiting)`: `id, description, type, status, due_date, due_time, document_id, medical_issue_id`, `order due_date asc nulls last` |
| `listIssuesFull()` | `medical_issues`: `id, name, status, next_step, created_at`, לפי `created_at` |
| `getIssue(id)` | בעיה אחת (`maybeSingle`). אם אין — המסך מציג "לא מצאנו את הבירור" עם קישור לנושאים |
| `listIssueTasks(issueId)` | כל המשימות של הבעיה, **כולל `done`**, `order due_date asc nulls last` |
| `listIssueDocuments(issueId)` | `documents`: `id, content_type, doc_date, provider, specialty, file_mime, created_at`, `order doc_date desc nulls last` |
| `getDocument(id)` | המסמך + `medical_issues(name, status)` (join דרך ה-FK), כולל `file_path, file_mime, input_text` |
| `updateIssue(id, {name, status, next_step})` | `update` |

**דשבורד:** שתי קריאות במקביל (`Promise.all`): `listOpenTasks` ו-`listIssuesFull`. מתוך הבעיות: שמות לכל שורת משימה (גם של בירור סגור, כי משימה פתוחה יכולה להיות משויכת לבירור שנסגר), והבירורים הפתוחים לאזור הבירורים.
**נושאים:** אותן שתי קריאות.
**בעיה:** שלוש קריאות במקביל: `getIssue`, `listIssueTasks`, `listIssueDocuments`.

## 5. הלוגיקה המחושבת (`js/case-state.js`)

פונקציות טהורות, בלי Supabase ובלי DOM, כדי שאפשר לבדוק אותן בנפרד.

- `NOW_WINDOW_DAYS = 14` — קבוע אחד (ARCHITECTURE 1.1).
- `todayISO()` — התאריך של היום לפי `Asia/Jerusalem` (`Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Jerusalem' })` → `YYYY-MM-DD`).
- `addDaysISO(iso, n)` — חשבון תאריכים על `YYYY-MM-DD` ב-UTC, בלי שעות.
- `splitDashboard(tasks, today)` → `{ now, later, waiting }`:
  - `now`: `todo` עם `due_date <= today + 14` (כולל שעבר). ממוין לפי תאריך.
  - `later`: שאר `todo`. ממוין לפי תאריך. (`todo` תמיד עם תאריך — אילוץ בטבלה.)
  - `waiting`: `waiting`, עם תאריך קודם (עולה), ובלי תאריך בסוף.
  - `done` לא מגיע לדשבורד בכלל.
  - בדיקת הגבול: היום+14 → `now`, היום+15 → `later`, אתמול → `now`.
- `issueState(issue, tasks)` → `'closed'` אם `status = closed`; אחרת `'action'` אם יש משימה `todo` של הבירור; אחרת `'waiting'` (כולל בירור בלי משימות פתוחות). **לא נשמר בטבלה.**
- `issueColor(state)` → טוקן הצבע (Coral / Amber / Slate).
- `openTaskTypes(issueId, tasks)` → רשימה ייחודית של סוגי המשימות הפתוחות (`todo`+`waiting`), בסדר של `lists.json`.
- `nextTaskForIssue` — **לא נדרש**: "הצעד הבא" הוא שדה `next_step` שהמשתמשת כותבת. אם הוא ריק — לא מציגים את השורה "הצעד הבא".

## 6. המסכים

### 6.1 דשבורד (`#/`) — DESIGN מסך 2 ו-13

**טלפון, מלמעלה למטה:**
1. כותרת Display: "שלום, הנה מה שדורש תשומת לב היום" — עם שם מנהלת התיק מ-`config/case.json` (ראו הנחה 1). `case.json` נטען ב-`main.js` יחד עם `lists.json`; אם נכשל — הכותרת בלי שם.
2. כפתור ראשי "הוספת מידע +" (קיים, טלפון בלבד).
3. **מה צריך לעשות עכשיו** — אזור Coral Zone: אייקון, H3, מונה ("2 משימות" / "משימה אחת"). שורה: אריח תאריך Coral Tint ("12 נוב׳"), שם המשימה, שורה משנית "נקודת צבע · שם הבעיה · סוג", וחץ (רק אם `document_id`). ריק: "אין כרגע משימות דחופות" (טקסט רגוע, ראו סעיף 7).
4. **מה ממתין** — אזור Amber Zone: אייקון סוג באריח, שם המשימה, "נקודה · שם הבעיה · עד 12.11" (בלי תאריך — בלי החלק "עד"), תג "ממתין" (מילה + אייקון), וחץ אם יש מסמך. ריק: "אין כרגע משימות שממתינות".
5. **בהמשך** — מתחת ל"מה ממתין". כפתור כותרת (`<button aria-expanded="false" aria-controls>`) עם H3 "בהמשך", מונה וחץ פתיחה. **מקופל כברירת מחדל.** פתוח: שורות באותו מבנה של "עכשיו", רקע לבן עם גבול Line, בלי צבע מצב. אם אין משימות — האזור לא מוצג.
6. **בירורים רפואיים פתוחים** — אזור Mint Zone, H2/H3, קישור טקסט "כל הנושאים" ← `#/issues`. כרטיס לכל בירור `open`: פס צבע בצד (לפי מצב), שם הבירור, "הצעד הבא: …" (אם יש), ותג מצב ("דורש טיפול" ברקע Soft Coral / "ממתין" ב-Amber Tint, עם אייקון). כל הכרטיס הוא קישור ל-`#/issue/:id`. ריק: "אין בירורים פתוחים" + קישור "בירור חדש".

**שם הבעיה בשורת משימה:** משימה ידנית בלי שיוך → מציגים "ללא שיוך" בלי נקודה (רלוונטי רק אחרי Milestone 5, אבל הקוד מטפל בזה כבר עכשיו).
**נקודת הצבע** בשורת משימה = צבע הבירור לפי מצבו.

**מחשב (≥ 1024px, לפי ה-breakpoint הקיים ב-CSS):** "מה צריך לעשות עכשיו" ו"מה ממתין" בשתי עמודות (עכשיו מימין). מתחתיהן "בהמשך" ברוחב מלא, מקופל. מתחתיו הבירורים בשורה אחת (grid של עד 3 בעמודה, גלישה לשורה הבאה). בשורות המשימה במחשב מוצג גם תג הסטטוס ("לביצוע" / "ממתין") ליד אריח התאריך. כפתור "הוספת מידע +" בכותרת (קיים).

**טעינה ושגיאה:** בזמן טעינה — טקסט טעינה קצר באזור התוכן; בשגיאה — `S.loadError` (קיים).

### 6.2 נושאים (`#/issues`) — DESIGN מסך 7

- H1 "נושאים", כפתור ראשי "בירור חדש +" (← `#/issue/new`), והסבר "כל הבעיות הרפואיות בתיק, עם הסטטוס והצעד הבא".
- **סדר:** בירורים פתוחים קודם (לפי `created_at`, מהחדש לישן — **הנחה 3**), ואחריהם הסגורים.
- **כרטיס פתוח:** פס צבע לפי מצב, שם, "הצעד הבא: …", תג מצב מחושב, תג סטטוס "פתוח" (Teal על #DCEDE9 + אייקון), ותגיות סוג של המשימות הפתוחות (תור, בדיקה, תרופה, תוצאה, החזר) — ללא תגיות אם אין.
- **כרטיס סגור:** דהוי (opacity 0.83 לפי DESIGN), פס Slate, שם הבירור ותג "סגור" בלבד. בלי תאריך, בלי צעד הבא, בלי תגיות.
- לחיצה על כרטיס ← `#/issue/:id` (גם סגור).
- ריק: "עדיין אין בירורים. אפשר לפתוח בירור חדש, או להוסיף מסמך ולפתוח אותו משם".

### 6.3 בעיה רפואית / בירור (`#/issue/:id`) — DESIGN מסך 8

- **כותרת** באזור Coral Zone: חץ חזרה, נקודת צבע (לפי מצב), שם הבירור (H1), כפתור "עריכה" עם אייקון עיפרון ← `#/issue/:id/edit`.
- תג סטטוס ("פתוח" / "סגור") ושורה "נפתח 12.10.2026" (מ-`created_at`, לפי `Asia/Jerusalem`). בבירור סגור גם השורה "נפתח" מוצגת (ההחלטה "בלי תאריך" חלה על כרטיס הנושאים בלבד).
- **הצעד הבא:** אזור צבעוני עם תיבה לבנה. ריק → "עוד לא נקבע צעד הבא" + קישור טקסט לעריכה.
- **משימות:** H3 "משימות" וכפתור "משימה חדשה" (ראו סעיף 1). כל שורה: אייקון סוג, שם, "עד 03.11" (לתור עם שעה: "עד 03.11, 09:30"), תג סוג, תג סטטוס (לא לחיץ עדיין), וחץ אם יש `document_id`. **כולל `done`.** סדר: `todo`, `waiting`, `done`, ובכל קבוצה לפי תאריך. ריק: "אין משימות בבירור הזה".
- **מסמכים:** H3 "מסמכים". שורת סינון (chips) נגללת לצדדים: "הכל" ואחריה כל `content_types` מ-`lists.json` (תווית "קבלה או חשבונית" כפי שבקובץ). chips הם `<button aria-pressed>`; לחיצה מסננת את הרשימה במקום, בלי טעינה מחדש. שורת מסמך (קישור ל-`#/document/:id`): אריח אייקון, **שם המסמך** = "סוג תוכן – תחום מומחיות" (למשל "סיכום ביקור – אורתופדיה", כמו ב-mockup; אם חסר אחד מהם — מה שיש; אם חסרים שניהם — "מסמך"), שורה משנית "12.10.2026 · נ. אבני" (תאריך המסמך וגורם מטפל; מה שחסר לא מוצג), וחץ. ריק לפי סינון: "אין מסמכים מהסוג הזה". ריק בכלל: "עוד אין מסמכים בבירור הזה".
- סרגל ניווט תחתון, "נושאים" פעיל.
- id לא קיים או לא תקין → הודעה "לא מצאנו את הבירור" + קישור לנושאים.

### 6.4 בירור חדש / עריכה (`#/issue/new`, `#/issue/:id/edit`) — DESIGN מסך 11

- טופס אחד, `renderIssueForm({ mode, issue })`. במצב יצירה — כמו היום (גם מתוך ה-Flow, בלי שינוי בהתנהגות של Milestone 3).
- **מצב עריכה:** כותרת "עריכת בירור" (**הנחה 2**), אותו משפט הסבר, השדות מלאים: שם, סטטוס (פתוח / סגור), צעד הבא. שמירה = `updateIssue`, ואז חזרה למסך הבעיה. **סגירת בירור** = בחירת "סגור" בשדה הסטטוס ושמירה (אין כפתור נפרד — PRD 4.3: "סטטוס (פתוח או סגור)").
- **יצירה מתוך "נושאים":** שמירה ואז חזרה ל"נושאים" (קיים, דרך `backPath`).
- id לא קיים → חזרה לנושאים.

### 6.5 המסמך המקורי של מסמך שמור (`#/document/:id`) — DESIGN מסך 6

- Flow frame: "המסמך המקורי" וחץ חזרה (← המסך הקודם: בעיה או בית).
- **שורת פרטים:** תג סוג תוכן (אם יש), נקודת צבע (לפי מצב הבירור — צריך גם את המשימות הפתוחות של הבירור; **פשוט יותר:** נקודה בצבע הבירור לפי `status` + בקשה קלה אחת `tasks where medical_issue_id = X and status = 'todo'` עם `count`), ו"12.10.2026 · כאבי גב תחתון" (תאריך המסמך ושם הבעיה; תאריך חסר — רק שם הבעיה).
- **התוכן** בלוח Mint Tint: תמונה — `createSignedUrl` ל-300 שניות, מוצגת עם `alt`; טקסט חופשי — `input_text`; PDF — כפתור "פתיחת הקובץ" שפותח את ה-signed URL בלשונית חדשה (אותו קוד כמו ב-Flow, בפונקציה משותפת).
- כשלון ביצירת הקישור → "לא הצלחנו לפתוח את הקובץ. אפשר לנסות שוב" (קיים).
- נפתח מ: שורת מסמך במסך הבעיה, חץ של משימה (דשבורד, מסך הבעיה).

4. **שם מסמך** ברשימת המסמכים: "סוג תוכן – תחום מומחיות", כמו בדוגמאות ב-mockup. אין בטבלה שדה "שם מסמך".

## 10. בדיקות בסוף הבנייה (שלי, לפני 🟡)

הרצה עם `npm run dev`, בדפדפן המובנה, ברוחב 375 ובמחשב. הרצה זו רק לבדיקות שלי, ונסגרת בסוף.

**לוגיקה (בלי מסד נתונים):** הרצת `case-state.js` בקונסול הדפדפן על נתונים מפוברקים בזיכרון:
- `splitDashboard`: אתמול → עכשיו; היום+14 → עכשיו; היום+15 → בהמשך; `waiting` בלי תאריך → אחרון ב"ממתין"; `done` → לא מופיע.
- `issueState`: יש `todo` → דורש טיפול; רק `waiting` → ממתין; בלי משימות פתוחות → ממתין; `closed` → סגור.

**על הנתונים האמיתיים (נתוני הדמה):**
- המשימה מהמסמך שנשמר ב-Milestone 3 מופיעה באזור הנכון לפי תאריך היעד שלה, עם שם הבעיה.
- אם בנתוני הדמה חסר אחד משלושת מקרי התאריך (עבר, +14, +15), **אעצור ואשאל** לפני שאוסיף שורות דמה זמניות לטבלה (יש פרויקט Supabase אחד, ARCHITECTURE 7.1), ואמחק אותן אחרי הבדיקה רק באישור.
- המסמך מופיע במסך הבעיה שלו פעם אחת; סינון לפי סוג משנה את הרשימה.
- יצירת בירור מ"נושאים", עריכה (שם, צעד הבא) וסגירה. אחרי סגירה: לא בדשבורד, מופיע דהוי ב"נושאים", ומסך הבעיה שלו עדיין נפתח עם המסמכים. (הבירור שנוצר לבדיקה נשאר בתיק — אין מחיקת בירורים. אשתמש בשם ברור, למשל "בירור בדיקה".)
- חץ במשימה ממסמך ← המסמך המקורי עם שורת הפרטים (תמונה, PDF, טקסט). משימה בלי `document_id` — בלי חץ (בנתוני הדמה; אם אין כזו, בדיקה בלוגיקה בלבד).
- ניווט במקלדת על הדשבורד ועל מסך הבעיה (Tab, Enter, פתיחת "בהמשך").
- אין שגיאות בקונסול; אין גלילה אופקית ב-375.
